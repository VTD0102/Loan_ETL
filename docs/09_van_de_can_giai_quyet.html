2.Mục tiêu của phần ML

2.1. Mục tiêu định lượng (Quantitative)

Hạng mụcHiện tạiMục tiêuCách đo
ROC-AUC LightGBM 0.7529 ≥ 0.78 Stratified 80/20 split + 5-fold CV (mean)
ROC-AUC LR Scorecard 0.7341 ≥ 0.76 Cùng test set với LightGBM
Recall (lớp Default) — LightGBM 65% ≥ 70% Threshold tuning theo F-beta (β=2)

Average Precision (AP) ~0.22 (LGBM) ≥ 0.25 Cho imbalanced data, quan trọng hơn AUC

2.2. Mục tiêu định tính (Qualitative)

  • Tách bạch decision & scoring — LightGBM cho approve/reject; LR Scorecard cho hiển thị điểm + giải thích.
  • Interpretability — mỗi quyết định có thể trace về top-3 feature đóng góp (SHAP cho LGBM, contribution_table cho LR).
  • Calibration — output probability của LightGBM phản ánh đúng default rate thực (không chỉ ranking).
  • Reproducibility — random_state=42, validate trước train, artifact joblib có version metadata.
  • Robust với missing data — model handle được EXT_SOURCE null 56% mà không crash.
  • Audit trail — mỗi training run log AUC + sample size + timestamp.

2.3. Mục tiêu kiến trúc (Architecture)

  • 2 models độc lập, cùng source data — đọc cùng gold.hc_features_v1 để consistency.
  • sklearn Pipeline đóng gói preprocessing + classifier — backend chỉ cần .predict_proba().
  • Joblib artifact với metadata đầy đủ — pipeline, feature_cols, thresholds, fico_params, contribution_table.
  • Validation gate bắt buộc — không bao giờ train trên data chưa validate.
  • Modular ETL — đổi feature engineering ở Gold không cần touch ML code.

7.LightGBM training (báo cáo #07)

Vấn đềTác độngĐề xuấtPriority
Backend chỉ pass 8 features, model expect 27 Endpoint /applications/submit sẽ crash khi gọi predict Backend cần JOIN gold để lấy 19 features còn lại theo user_id Cao
Chưa Optuna hyperparameter tuning Mất ~+0.5–1.5% AUC tiềm năng 50 trials, 5-fold CV, optimize ROC-AUC Cao
Single 80/20 split, không CV AUC có variance giữa các seed; metric không stable 5-fold stratified CV, report mean ± std Trung bình
Không có early stopping 400 trees có thể overfit ở tree thứ 200 Tách validation 10% từ train, monitor AUC mỗi 50 trees Trung bình
Recall lớp Default chỉ 65% 35% default bị miss → không đạt mục tiêu ≥ 70% Tune threshold dựa trên F-beta (β=2) hoặc cost function Trung bình
Calibration chưa kiểm tra P(default) output có thể không phản ánh thực Plot calibration curve; nếu lệch → CalibratedClassifierCV Trung bình

10.Priority roadmap

Top 8 Priority CAO — cần xử lý trước

  1. Backend pass đủ 27 features cho LightGBM — JOIN gold theo user_id (Backend)
  2. Build endpoint /credit-score/{id} trả score + breakdown (Backend)
  3. Build Frontend CreditDashboard hiển thị score + factor breakdown (Frontend)
  4. Optuna tuning LightGBM → +0.5–1.5% AUC, tiến gần mục tiêu ≥ 0.78 (ML)
  5. Add has_history flag để model phân biệt "không có" vs "tốt" (Gold)
  6. Validate gold layer — không chỉ silver (Validation)
  7. Fix Scorecard signs ngược — income_verifiable_flag, breakdown qua API (ML)
  8. Tăng score range scorecard 300–850 thực sự → đạt spread ≥ 300 điểm (ML)

Priority TRUNG BÌNH — sau khi xong 8 việc trên

  1. 5-fold CV cho cả 2 model + early stopping
  2. Calibration LightGBM (probability calibration)
  3. SHAP integration cho LightGBM
  4. Bureau aggregates mở rộng (12 fields còn lại)
  5. RAG context với credit_score + top-3 SHAP factors
  6. Data drift detection
  7. Unit test ML pipeline
  8. employment_length_years feature từ DAYS_EMPLOYED
  9. Monotonic constraints cho scorecard
  10. FICO params calibration theo dataset
