2.RAG cần gì từ model?

RAG không trực tiếp "train" model ML. RAG cần model ML tạo ra dữ liệu đáng tin cậy để đưa vào prompt: default_probability, risk_level, risk_score, hạn mức/kỳ hạn đề xuất, và nếu có thể là các yếu tố giải thích.

Thành phầnVai trò trong RAGYêu cầu tối thiểu
customer_risk_model.pkl Tạo P(default), phân loại Low/Medium/High, làm context cá nhân hóa. Inference không fallback mock, output được lưu vào loan_applications.
scorecard_model.pkl Giải thích điểm tín dụng 300-850 và top factors cho khách hàng. Endpoint /credit-score chạy được với application thật.
Knowledge base Cung cấp policy, FAQ, data dictionary để LLM trả lời có nguồn. Đã ingest vào vector DB, retrieve được source documents.
LLM + prompt Ghép user context + retrieved docs thành câu trả lời tiếng Việt. Có guardrails, từ chối ngoài phạm vi, không hứa phê duyệt.

3.2. RAG backend

3.3. Knowledge base

Knowledge base hiện có policy.md và faq.md. Nội dung đủ cho câu hỏi phổ biến: lý do AUTO_REJECTED, ý nghĩa Low/Medium/High, DTI, credit score, đề xuất hạn mức và quy trình sau duyệt. Đây là mức đủ cho chatbot tư vấn cơ bản, nhưng chưa đủ cho audit hoặc compliance đầy đủ.

4.Điểm đủ dùng

  • Đã có đường đi dữ liệu cá nhân hóa: build_user_context() đọc application mới nhất và đưa P(default), risk_level, hạn mức vào prompt.
  • Đã có knowledge retrieval: ingest Markdown vào Pinecone, retrieve top-k, đưa vào prompt dưới biến {context}.
  • Prompt có guardrails cơ bản: chỉ trả lời về khoản vay/tín dụng, không hứa phê duyệt, không tiết lộ khách hàng khác.
  • Model có output phù hợp cho RAG: xác suất vỡ nợ, risk level, risk score và recommendation đều là thông tin dễ giải thích bằng LLM.
  • Scorecard bổ sung interpretability: có thể dùng endpoint /credit-score để giải thích điểm tín dụng nếu tích hợp vào chat context.

5.Điểm chưa đủ

5.1. Contract giữa training và inference có dấu hiệu lệch

machinelearning/ml/retrain_customer_model.py hiện định nghĩa nhiều feature Gold/Home Credit như ext_source_1, num_previous_loans, num_bureau_records, age_years, education_ordinal và các demographic flags. Trong khi đó backend/services/ml_service.py chỉ gửi 8 field từ form khách hàng.

Nếu artifact hiện tại đúng theo code training mới, backend prediction sẽ thiếu cột và rơi vào block except, sau đó trả mock probability. Khi RAG dựa trên context này, chatbot có thể giải thích một kết quả không phải từ model thật. 

# Backend hiện chỉ tạo 8 fields:
monthly_income, loan_amount, term, employment_status,
dti, is_homeowner, listing_category, credit_score

# Training hiện có thêm nhiều fields:
ext_source_1, ext_source_3, bureau features,
previous application features, demographic features...

5.2. Schema chat SQL và SQLAlchemy chưa đồng nhất

NguồnSchema đang mô tảRủi ro

5.3. Chưa có bằng chứng Pinecone ingest đã chạy

Code ingest đã có, nhưng cần chạy và xác nhận index creditintel-kb có vector. Nếu chưa ingest, retriever sẽ không có source documents, LLM chỉ còn user context và dễ trả lời thiếu căn cứ.

5.4. RAG chưa có evaluation set

Chưa thấy bộ câu hỏi kiểm thử cho RAG. Cần tối thiểu 15-20 câu hỏi bao phủ: policy, FAQ, câu hỏi theo hồ sơ cá nhân, câu hỏi ngoài phạm vi, câu hỏi đòi tiết lộ model/khách hàng khác, và câu hỏi khi user chưa có đơn vay.

5.5. Error handling đang lộ chi tiết nội bộ

chat_service.py trả trực tiếp nội dung exception vào answer: Lỗi truy vấn nội bộ RAG/LLM: {str(e)}. Với demo nội bộ thì chấp nhận được, nhưng production nên log server-side và trả thông báo chung.

7.Checklist cần hoàn tất

7.1. Bắt buộc trước khi demo cá nhân hóa

  • Load customer_risk_model.pkl bằng joblib và in ra feature_cols, thresholds.
  • Sửa ml_service.py để feature input khớp artifact, hoặc retrain artifact chỉ dùng đúng 8 feature form.
  • Bỏ hoặc hạn chế fallback mock trong luồng demo RAG; nếu fallback thì phải gắn cờ prediction_source = mock và không để chatbot giải thích như model thật.
  • Chạy python -m backend.rag.ingest và xác nhận Pinecone index có vectors.
  • Gửi thử POST /chat với user có application mới nhất và kiểm tra answer có dùng đúng risk context.

7.2. Bắt buộc trước production

  • Đồng bộ schema chat_messages giữa SQL init và SQLAlchemy model.
  • Thêm RAG eval set: câu hỏi, expected behavior, source expected, pass/fail.
  • Không trả raw exception cho user; log lỗi bằng server logger.
  • Thêm citation từ source_documents vào response schema nếu frontend cần hiển thị nguồn.
  • Thêm kiểm thử regression cho các guardrails: không hứa phê duyệt, không tiết lộ khách hàng khác, không trả lời ngoài phạm vi.
  • Version hóa knowledge base và model artifact để biết mỗi câu trả lời dùng phiên bản nào.

Kết luận cuối

Nếu mục tiêu là demo module RAG trong project, hiện trạng đã gần đủ nhưng phải sửa/verify ML inference trước. Nếu mục tiêu là chatbot dùng thật, cần hoàn tất checklist production. RAG chỉ mạnh khi context đúng; nếu risk score là mock hoặc schema DB lệch, LLM sẽ trả lời trôi chảy nhưng không đáng tin.
