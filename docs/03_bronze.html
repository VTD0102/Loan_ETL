1.Tóm tắt báo cáo

Bronze là lớp thấp nhất trong kiến trúc Medallion (Bronze → Silver → Gold). Mục tiêu duy nhất: nhập nguyên trạng CSV từ Kaggle vào DuckDB để các layer trên xử lý. Không biến đổi, không clean, không feature engineering ở giai đoạn này.

2.Vai trò của Bronze layer

2.1. Nguyên tắc thiết kế

Medallion Architecture (Databricks pattern) — chia data warehouse thành 3 lớp tăng dần về chất lượng:

  • Bronze — raw, immutable, "single source of truth" từ nguồn.
  • Silver — cleaned, conformed, schema chuẩn hoá.
  • Gold — business-ready, feature engineered, có thể serve thẳng cho ML/BI.

2.2. Tại sao cần Bronze riêng (không nhảy thẳng vào Silver)?

  • Reproducibility — nếu silver SQL có bug, có thể re-run từ bronze mà không cần re-download CSV.
  • Audit trail — giữ raw để truy nguyên: "tại sao giá trị này có?" → check bronze.
  • Idempotency — CREATE OR REPLACE TABLE trên bronze cho phép rerun an toàn.
  • Decoupling — đổi schema silver không cần re-load CSV.

4.Quy trình load

4.1. Pseudocode

1. Mở DuckDB connection (read-write)
2. CREATE SCHEMA IF NOT EXISTS bronze
3. Cho mỗi CSV:
   a. pandas.read_csv(path, usecols=COLS) — chỉ load cột cần
   b. con.execute("CREATE OR REPLACE TABLE bronze.X AS SELECT * FROM df")
4. Verify row counts
5. Đóng connection

4.2. Pattern code chính

import duckdb, pandas as pd

df = pd.read_csv(CSV_PATH, usecols=COLS, low_memory=False)

con = duckdb.connect('machinelearning/data/etl.duckdb')
con.execute("CREATE SCHEMA IF NOT EXISTS bronze")
con.execute("CREATE OR REPLACE TABLE bronze.home_credit_raw AS SELECT * FROM df")
con.close()

5.Quyết định kỹ thuật quan trọng

5.1. Native DuckDB API thay vì SQLAlchemy

Lý do

Ban đầu dùng pandas.to_sql() qua SQLAlchemy. Nhưng to_sql() với if_exists="replace" gọi reflect() để check table tồn tại — query này yêu cầu pg_catalog.pg_collation (PostgreSQL-specific) → DuckDB throw lỗi.

Fix: dùng native duckdb.connect() + CREATE OR REPLACE TABLE ... AS SELECT * FROM df — DuckDB tự infer schema từ pandas DataFrame.

5.2. Column subsetting (load 19/122 cột)

CSV gốc có 122 cột, nhiều cột không dùng đến (e.g. FLAG_DOCUMENT_3..21, APARTMENTS_AVG...). Load đầy đủ tốn ~500MB memory. Subset 19 cột → ~30MB. Tradeoff: nếu cần thêm cột phải sửa COLS và re-run.

5.3. DAYS_EMPLOYED placeholder 365243

Trong Home Credit, DAYS_EMPLOYED = 365243 (1000 năm) là magic value đánh dấu "không applicable" (e.g. người về hưu, sinh viên). Bronze giữ nguyên giá trị này; Silver layer sẽ xử lý.

5.4. Chỉ load 3/7 bảng

Project bỏ qua installments_payments.csv (13.6M rows) và credit_card_balance.csv (3.8M rows) vì:

  • Kích thước quá lớn, làm chậm pipeline trong khi gain AUC marginal (~+1–2%).
  • Có thể add sau khi cần boost performance ở Phase 4.
