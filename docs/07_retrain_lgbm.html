1.Tóm tắt báo cáo

LightGBM là model chính dự đoán xác suất default. Output P(default) ∈ [0, 1] được dùng làm input cho decision logic backend (approve/reject/review). Pipeline được tách rời: preprocessing (encoder) → classifier (LGBM), đóng gói qua sklearn Pipeline, lưu joblib.

Tốc độ train ~10–15s trên 240k rows × 27 features (8 customer-input + 14 rich + 6 demographics). Inference ~1ms per row → đủ cho real-time API endpoint.

4.Pipeline & hyperparameters

4.1. sklearn Pipeline structure

preprocessor = ColumnTransformer([
    ("num", "passthrough",       NUMERIC_FEATURES),    # LightGBM xử lý numeric trực tiếp
    ("cat", OrdinalEncoder(handle_unknown="use_encoded_value", unknown_value=-1),
     CATEGORICAL_FEATURES),
])

pipeline = Pipeline([
    ("preprocessor", preprocessor),
    ("classifier",   LGBMClassifier(
        n_estimators=400,
        learning_rate=0.05,
        num_leaves=31,
        max_depth=-1,
        min_child_samples=50,
        reg_alpha=0.1,
        reg_lambda=0.1,
        is_unbalance=True,
        random_state=42,
        n_jobs=-1,
        verbose=-1,
    )),
])

4.2. Tại sao "passthrough" cho numeric?

LightGBM (giống XGBoost) không yêu cầu standardize — vì split trên decision tree dựa trên ngưỡng (threshold), không phải khoảng cách. Bỏ StandardScaler tiết kiệm thời gian fit, giảm thêm 1 layer phải debug.

4.3. Các hyperparameter quan trọng

ParamGiá trịVai trò
n_estimators400Số trees — đủ để học pattern nhưng không overfit
learning_rate0.05Step size — nhỏ hơn = stable hơn nhưng cần nhiều tree
num_leaves31Số lá tối đa mỗi tree (chuẩn LightGBM)
min_child_samples50Số sample tối thiểu trong 1 lá → tránh overfit
reg_alpha0.1L1 regularization

5.3. Decision thresholds

LOW_THRESHOLD  = 0.20
HIGH_THRESHOLD = 0.40

if prob < LOW_THRESHOLD:        risk_level = "Low"     →  Approve, gợi ý $15,000 / 36 tháng
elif prob <= HIGH_THRESHOLD:    risk_level = "Medium"  →  Review, gợi ý $8,000  / 24 tháng
else:                            risk_level = "High"    →  Reject, gợi ý $3,000  / 12 tháng

6.1. Cấu trúc artifact .pkl

{
    "pipeline":     sklearn.Pipeline(...),        # full preprocessor + classifier

}

6.2. Loading trong backend

# backend/services/ml_service.py
MODEL_PATH = Path(__file__).parents[2] / "ml" / "models" / "customer_risk_model.pkl"

_artifact = None
def _load():
    global _artifact
    if _artifact is None:
        _artifact = joblib.load(MODEL_PATH)   # <-- load 1 lần, cache singleton
    return _artifact

6.3. Prediction flow

def predict(payload):
    artifact  = _load()
    row = pd.DataFrame([{...8 features...}])   # backend chỉ pass 8 customer-input features
    prob = artifact["pipeline"].predict_proba(row)[0, 1]
    return {"default_probability": prob, "risk_level": ..., ...}

Chú ý: Backend hiện chỉ pass 8 features. 19 rich/demo features sẽ thiếu → sẽ raise error vì pipeline expect 27 features. Cần xử lý: backend cần query gold layer để lấy 19 features còn lại cho user_id tương ứng, hoặc model cần train lại với 8 features (giảm AUC).
