1.Tóm tắt báo cáo

Silver là lớp clean của Medallion. Đầu vào: bronze.home_credit_raw (raw CSV). Đầu ra: silver.home_credit_cleansed — 36 cột với schema chuẩn hoá, type ép đúng, và outlier đã loại.

Silver được thiết kế để tương thích với schema gold tổng quát (tên cột giống với silver.prosper_loans_cleansed nếu có), giúp ML model có thể dùng cùng query bất kể nguồn data. Filter 2 điều kiện: DTI ∈ [0,5] và monthly_income > 0 — bỏ ~6,500 rows outlier.

2.Vai trò của Silver layer

2.1. Trách nhiệm

  • Schema standardization — đổi tên cột HC sang tên CreditIntel (e.g. SK_ID_CURR → listing_key).
  • Type casting — ép TEXT → NUMERIC/INT/TIMESTAMP rõ ràng để gold không phải xử lý.
  • Outlier removal — bỏ rows có DTI quá cao, income ≤ 0, target null.
  • Derived columns đơn giản — DTI, term, income_range — chưa phải feature engineering nâng cao (đó là việc của Gold).
  • NULL handling explicit — dùng CASE WHEN ... IS NULL rõ ràng, không silent fallback.

2.2. KHÔNG phải trách nhiệm của Silver

  • Aggregation từ bảng khác (bureau, previous_application) → thuộc Gold.
  • Tính ratio/log/flag từ 2+ cột → thuộc Gold.
  • Encoding categorical → thuộc ML pipeline.
  • Imputation phức tạp (KNN, MICE) → thuộc ML pipeline.

4.Các transformation chính

4.1. Tính term (số tháng vay)

Home Credit không có cột "term" trực tiếp. Tính theo công thức: term ≈ AMT_CREDIT / AMT_ANNUITY (tổng vay / tiền trả tháng). Clamp 12–60 để loại outlier. 

CASE
  WHEN AMT_ANNUITY IS NOT NULL AND AMT_ANNUITY > 0
  THEN GREATEST(12, LEAST(60, ROUND(AMT_CREDIT / AMT_ANNUITY)::INT))
  ELSE 36
END AS term

4.2. Tính DTI

DTI = monthly_payment / monthly_income = AMT_ANNUITY / (AMT_INCOME_TOTAL / 12). Round 5 chữ số để consistency.

4.3. Credit score 300–850 từ EXT_SOURCE_2

EXT_SOURCE_2 chuẩn hoá 0.0–1.0 → map sang FICO 300–850 bằng 300 + EXT_SOURCE_2 × 643. Multiplier 643 chọn vì giá trị thực max của EXT_SOURCE_2 là 0.855 → 0.855 × 643 ≈ 550, đạt đúng 850. Clamp ±25 ra range_lower/range_upper.

4.5. income_verifiable flag

Set TRUE nếu cả 3 điều kiện: FLAG_EMP_PHONE = 1, DAYS_EMPLOYED ≠ 365243 (placeholder), và DAYS_EMPLOYED IS NOT NULL.

4.6. Demographic features (Phase 3)

  • age_years = -DAYS_BIRTH / 365.25 — convert ngày sinh âm sang tuổi dương.
  • gender — pass-through M/F/XNA, Gold sẽ encode về flag 0/1.
  • education_type, family_status — pass-through, Gold sẽ ordinal/group.

4.7. Filter cuối

WHERE debt_to_income_ratio IS NOT NULL
  AND debt_to_income_ratio BETWEEN 0 AND 5    -- loại outlier DTI cực đoan
  AND stated_monthly_income > 0;

5.Quyết định kỹ thuật

5.1. Tại sao quoted column names trong SQL?

Bronze tables được tạo từ pandas.DataFrame.to_sql() (trước khi đổi sang native DuckDB) — pandas giữ tên cột uppercase từ CSV (SK_ID_CURR). DuckDB SQL nếu unquoted sẽ lowercase tự động (sk_id_curr) → mismatch → error.

Fix: dùng double-quote trong SQL: "SK_ID_CURR"::TEXT để preserve case.

5.2. Tại sao có cột NULL cố ý (loan_key, occupation...)?

Để tương thích schema với silver.prosper_loans_cleansed (nếu có). Các cột này tồn tại nhưng giá trị NULL — gold layer query vẫn chạy được. Sau khi gold transform, các cột vô dụng sẽ bị bỏ.

5.3. EXT_SOURCE_1/3 expose nhưng KHÔNG dùng tính credit_score

Chỉ EXT_SOURCE_2 được dùng để tính credit_score_range vì có null rate thấp nhất (0.2%). EXT_SOURCE_1 (null 56%) và EXT_SOURCE_3 (null 19.8%) được expose riêng làm feature độc lập cho ML model — không trộn vào credit_score để tránh leak signal.
