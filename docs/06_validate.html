1.Tóm tắt báo cáo

Validate là gate bắt buộc trước khi train model. Script machinelearning/ml/validate_data.py chạy 6 checks trên silver.home_credit_cleansed, raise ValidationError nếu bất kỳ check nào fail — ngăn train trên data hỏng.

Nguyên tắc: fail fast, fail loud. Thay vì để model train trên data hỏng rồi metric tệ (khó debug), validate sẽ dừng ngay với thông báo cụ thể giúp dev fix nguyên nhân gốc.

2.Vai trò & nguyên lý

2.1. Tại sao cần validate?

Trong pipeline ETL → ML, nhiều thứ có thể sai âm thầm:

  • Silver ETL chạy nhưng filter quá nghiêm → còn 100 rows → model trash nhưng vẫn train.
  • Một cột bị rename trong SQL → ML query fail mơ hồ tại bước fit.
  • Default rate đột nhiên 50% (data bug) → model học pattern sai.
  • Credit score lệch ra ngoài [300, 850] → output không hợp lệ.

Validate phát hiện các vấn đề này trước khi tiêu tốn 15s train, và quan trọng hơn — trước khi report metric sai cho stakeholder.

2.2. Nguyên lý "evidence before assertions"

Không claim "data sạch" mà kiểm chứng. Mỗi check trả về số liệu cụ thể (row count, null %, default rate), không chỉ pass/fail. Người dev có thể track số theo thời gian để detect data drift.

3.2. Check #2 — Schema (required columns)

Đảm bảo cả 10 cột bắt buộc tồn tại trong silver: 

REQUIRED_COLUMNS = {
    "stated_monthly_income", "loan_original_amount", "term",
    "employment_status", "debt_to_income_ratio", "is_homeowner",
    "listing_category_id", "credit_score_range_lower",
    "credit_score_range_upper", "is_default"
}

Threshold: missing = ∅. Nếu set difference khác rỗng → fail kèm danh sách cột thiếu.

3.3. Check #3 — Null rates (critical columns)

Threshold: MAX_NULL_RATE_PCT = 5.0% cho 3 cột (income, loan, dti), 0% cho target. 

SELECT
    ROUND(100.0 * AVG(CASE WHEN stated_monthly_income IS NULL THEN 1 ELSE 0 END), 2) AS income,
    ROUND(100.0 * AVG(CASE WHEN loan_original_amount   IS NULL THEN 1 ELSE 0 END), 2) AS loan,
    ROUND(100.0 * AVG(CASE WHEN debt_to_income_ratio   IS NULL THEN 1 ELSE 0 END), 2) AS dti,
    ROUND(100.0 * AVG(CASE WHEN is_default             IS NULL THEN 1 ELSE 0 END), 2) AS target
FROM silver.home_credit_cleansed

Special case: target null không bao giờ được chấp nhận (vì không thể train supervised mà thiếu y).

3.4. Check #4 — Default rate (class balance)

Threshold1% ≤ default_rate ≤ 50%
Lý do lower< 1% = quá lệch, model không học được pattern minority
Lý do upper> 50% = data có thể bị flip target hoặc bị filter sai
Current8.07% ✓

3.5. Check #5 — Credit score range (FICO 300–850)

Kiểm tra mọi giá trị credit_score_range_lower ≥ 300 và credit_score_range_upper ≤ 850. Nếu lệch → silver SQL formula có bug (e.g. clamp sai). 

SELECT MIN(credit_score_range_lower) AS lo,
       MAX(credit_score_range_upper) AS hi
FROM silver.home_credit_cleansed
WHERE credit_score_range_lower IS NOT NULL

3.6. Check #6 — Employment status values

Đảm bảo các giá trị thuộc whitelist 6 giá trị defined: 

EXPECTED_EMPLOYMENTS = {
    "Employed", "Self-employed", "Retired",
    "Not employed", "Unemployed", "Other"
}

Nếu silver sinh ra giá trị lạ (e.g. "Pensioner" chưa được map) → fail. Đây là cách bắt được lỗi silent mapping miss khi update silver SQL.

4.Logic xử lý fail

4.1. ValidationError exception

class ValidationError(Exception):
    pass


def validate():
    ...
    if n_rows < MIN_ROWS:
        raise ValidationError(f"Quá ít rows: {n_rows:,} < {MIN_ROWS:,}")
    ...

4.2. CLI exit code khi gọi standalone

if __name__ == "__main__":
    try:
        validate()
    except ValidationError as e:
        print(f"\n❌ VALIDATION FAILED: {e}")
        sys.exit(1)    # exit code ≠ 0 cho CI/CD detect

4.3. Propagation trong training

Khi gọi từ retrain_customer_model.py hoặc train_scorecard.py: nếu validate() throw, training cũng dừng ngay — model file không bị overwrite, artifact cũ vẫn an toàn.
