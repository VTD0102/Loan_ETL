# Person 4 — ML & Risk System Documentation

## Overview

This document describes the Machine Learning and Risk Assessment system built for the **Loan ETL Project** as part of the database management course.  
Person 4 is responsible for the full prediction pipeline: training the model, generating risk assessments, and persisting results to the database.

---

## Role in the Pipeline

```
bronze → silver → core → gold → [ML PREDICTION] → core.risk_assessment
                                  ↑ Person 4 owns this layer
```

Person 4 takes the output of **Person 3** (`gold.loan_features_v1`) as input and produces structured risk assessment results saved back into the `core` schema.

## `train_model.py`

### What It Does

Fetches the full feature table from `gold.loan_features_v1`, trains a binary classification model to predict loan default (`is_default = 1`), evaluates it on a held-out test set, and saves the trained artifact to disk.

### Execution

```bash
# Run from project root
python -m ml.train_model
```

### Step-by-Step Flow

```
[1/6] Connect to Supabase via get_engine()
[2/6] Fetch all rows from gold.loan_features_v1
[3/6] Drop non-numeric columns + fill nulls with median
[4/6] Split data 80/20 (stratified by is_default)
[5/6] Train Pipeline: StandardScaler → RandomForestClassifier
[6/6] Evaluate on test set → print metrics
      Save artifact: pipeline + feature_cols + thresholds → loan_risk_model.pkl
```

### Technologies & Techniques

| Technology | Usage |
|-----------|-------|
| `scikit-learn` | `Pipeline`, `StandardScaler`, `RandomForestClassifier` |
| `sklearn.model_selection` | `train_test_split` with `stratify=y` |
| `sklearn.metrics` | `roc_auc_score`, `f1_score`, `classification_report` |
| `pandas` | Data loading, null handling, type filtering |
| `joblib` | Model serialization to `.pkl` |
| `SQLAlchemy` | Database connection via shared `get_engine()` |
| `PyYAML` | Config loading from `settings.yaml` |
| `pathlib` | Cross-platform path resolution |

### Key Technical Decisions

**Stratified train/test split**  
Uses `stratify=y` to preserve the 85%/15% default ratio in both train and test sets. Without this, the test set might not represent the real class distribution.

**Non-numeric column filtering**  
`select_dtypes(include=['number'])` is applied before fitting. This prevents `StandardScaler` from crashing on string columns like `borrower_state`, `prosper_rating_alpha`, etc.

**Null handling with median imputation**  
10 columns had missing values (e.g. `debt_to_income_ratio`, `prosper_score`). These are filled with column medians to prevent NaN propagation through the scaler.

**`class_weight='balanced'`**  
The dataset is imbalanced: 84.9% non-default vs 15.0% default. `balanced` automatically adjusts class weights inversely proportional to frequency, preventing the model from just predicting the majority class.

**Tuned RandomForest hyperparameters**  
```python
n_estimators=200      # more trees = more stable predictions
max_depth=15          # prevents overfitting on deep trees
min_samples_leaf=5    # each leaf needs at least 5 samples
min_samples_split=10  # need 10 samples before splitting a node
```

**Artifact saves 3 keys**  
```python
{
    'pipeline'    : trained_pipeline,
    'feature_cols': list_of_34_column_names,
    'thresholds'  : {'low': 0.2, 'high': 0.4}
}
```
`feature_cols` is critical — `predict_engine.py` uses it to align columns exactly at prediction time.

### Model Performance (Final)

| Metric | Value |
|--------|-------|
| ROC-AUC | **0.8643** |
| F1-Score (Default) | **0.5136** |
| Recall (Default) | **0.76** |
| Precision (Default) | **0.39** |
| Accuracy | **0.78** |
| Training rows | 90,452 |
| Test rows | 22,614 |
| Features used | 34 numeric columns |

> **ROC-AUC 0.8643** means the model correctly ranks a risky loan above a safe loan 86.4% of the time — a strong result for credit risk modeling.

> **Recall 0.76** means the model catches 76% of actual defaults — up from 0.25 before tuning.

## `predict_engine.py`

### What It Does

Accepts a `loan_number` (integer), validates it against `core.loans`, fetches its features from `gold.loan_features_v1`, runs the trained model, and saves a full risk assessment to `core.risk_assessment`.

### Execution

```bash
# Run from project root
python -m ml.predict_engine 65928
```

### Step-by-Step Flow

```
[1/5] Validate loan_number exists in core.loans
      → Retrieve listing_key (VARCHAR primary key)
[2/5] Load model artifact from ml/models/loan_risk_model.pkl
      → Extract pipeline, feature_cols, thresholds
[3/5] Fetch features from gold.loan_features_v1 WHERE listing_key = ...
      → Drop non-model columns
      → Align to exact feature_cols order
      → Fill any nulls with median
[4/5] Run pipeline.predict_proba(X)
      → Calculate risk_level, risk_score_internal, recommendation
[5/5] DELETE existing record for listing_key (upsert pattern)
      → INSERT new result into core.risk_assessment
```

### Technologies & Techniques

| Technology | Usage |
|-----------|-------|
| `scikit-learn` | Load and run trained pipeline |
| `joblib` | Deserialize `.pkl` artifact |
| `pandas` | Feature preparation, `to_sql()` insert |
| `SQLAlchemy` | `text()` queries, `engine.begin()` transactions |
| `pathlib` | Cross-platform model path resolution |
| `datetime + timezone` | UTC timestamps for `assessment_date` |

### Key Technical Decisions

**Two-step key resolution**  
`loan_number` (integer input) → `listing_key` (VARCHAR) via `core.loans`.  
This is necessary because `gold.loan_features_v1` uses `listing_key` as its primary key, not `loan_number`.

```sql
SELECT listing_key FROM core.loans
WHERE loan_number = CAST(:loan_number AS VARCHAR)
```

**Column alignment via saved `feature_cols`**  
At prediction time, `gold.loan_features_v1` has more columns than the model was trained on (string columns, date columns, etc.). The saved `feature_cols` list from the artifact is used to select and order exactly the right 34 columns.

```python
X = X[feature_cols]  # exact order required by StandardScaler
```

**Upsert pattern (DELETE + INSERT)**  
Before saving, any existing record for the same `listing_key` is deleted. This prevents duplicate rows when the same loan is assessed multiple times.

**Thresholds from artifact**  
Risk level thresholds are loaded from the saved artifact rather than hardcoded. This guarantees the same thresholds used during training evaluation are applied at prediction time.

### Risk Business Rules

| Probability of Default | Risk Level | Recommended Amount | Recommended Term |
|------------------------|------------|-------------------|-----------------|
| < 0.20 | Low | $15,000 | 36 months |
| 0.20 – 0.40 | Medium | $8,000 | 24 months |
| > 0.40 | High | $3,000 | 12 months |

### Internal Risk Score Formula

```
risk_score_internal = (1 - probability_of_default) × 100
```

Higher score = safer borrower. Range: 0 (certain default) to 100 (no default risk).

## `core.risk_assessment` Table Schema

Created via `init_risk_assessment.sql` in Supabase SQL Editor.

```sql
CREATE TABLE core.risk_assessment (
    id                      SERIAL PRIMARY KEY,
    listing_key             VARCHAR(100) NOT NULL,
    loan_number             VARCHAR(50),
    probability_of_default  NUMERIC(6, 4),
    risk_score_internal     INTEGER,
    risk_level              VARCHAR(10) CHECK (risk_level IN ('Low', 'Medium', 'High')),
    recommended_amount      NUMERIC(12, 2),
    recommended_term        INTEGER,
    assessment_date         TIMESTAMPTZ,
    CONSTRAINT uq_risk_assessment_listing_key UNIQUE (listing_key),
    CONSTRAINT fk_risk_assessment_loan
        FOREIGN KEY (listing_key) REFERENCES core.loans(listing_key)
);
```

| Column | Type | Description |
|--------|------|-------------|
| `id` | SERIAL | Auto-increment primary key |
| `listing_key` | VARCHAR(100) | FK → `core.loans.listing_key` |
| `loan_number` | VARCHAR(50) | Human-readable loan number |
| `probability_of_default` | NUMERIC(6,4) | Model output: 0.0000 – 1.0000 |
| `risk_score_internal` | INTEGER | Inverted score: 0 (worst) – 100 (best) |
| `risk_level` | VARCHAR(10) | Low / Medium / High |
| `recommended_amount` | NUMERIC(12,2) | Suggested loan amount |
| `recommended_term` | INTEGER | Suggested term in months |
| `assessment_date` | TIMESTAMPTZ | UTC timestamp of assessment |
